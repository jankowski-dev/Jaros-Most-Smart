## TL;DR для агента

- Стек не меняем: vanilla JS (ES modules) + Tailwind CSS 4 + Express-прокси. React/MUI не добавляем.
- **Главный девайс — планшет 10″ (портрет и ландшафт), второй — телефон, десктоп — редко.** Проектируем tablet-first и touch-first; десктоп получает ту же раскладку с ограничением ширины, без отдельного «десктопного» UI.
- Стиль: Material You-inspired, светлая тема по умолчанию + тёмная; бренд — тёплый янтарный; маскот — робо-паук **Байт**.
- Главная — дашборд, а не меню из четырёх строк. Навигация: **Учиться / Прогресс / Настройки**.
- Появляются XP, уровни, звёзды, серия дней, бейджи и цель дня. Прогресс хранится в `localStorage`.
- Длительность сессий: математика — 10 заданий, чтение — 20 карточек (слов или фраз), тест — 10 слов.
- Никаких искусственных лоадеров на 0,5–0,7 секунды. Переходы мгновенные, с короткими анимациями.
- Сохраняем PWA, офлайн-режим, Yandex TTS + браузерный fallback и анимацию заливки слова.
- `styles.css` генерируется Tailwind — руками не редактировать.
- После реализации обновить `AGENTS.md`, `README.md`, `sw.js` и версию до `3.0`.

## 1. Контекст

Сейчас «Ярик.Уроки» — рабочая PWA для одного ребёнка: математика, чтение и тест на слух. Технически база крепкая: офлайн-кэш, синтез речи с fallback, клавиатурный ввод, адаптив. Lighthouse: accessibility 98, best practices 100.

Но интерфейс выглядит бедно:

- главная — список из четырёх строк, 60–70% десктопного экрана пустует;
- урок и тест — таймер и кнопки сверху, задание висит в белом поле;
- настройки — заглушка, пункт меню даже не кликается;
- результаты никуда не сохраняются;
- тест маскирует слово случайными символами (иногда получается «8СМ»), нет явной кнопки повторного прослушивания;
- искусственный лоадер задерживает каждый переход;
- `app.js` — 1669 строк с глобальным состоянием, `data.js` смешивает контент и разметку слогов через дефисы.

При этом приложение уже персональное: в ответах есть «Ярослав», «Ярик». Его надо не просто «накрасить», а превратить в маленький игровой тренажёр, в который семилетний ребёнок заходит сам.

## 2. Кто пользователь

**Ярик, 7 лет.** Читает слоги и простые слова, считает в пределах 10–20. Любит роботов и пауков, особенно робо-пауков. Взрослый рядом не всегда.

**Устройства (по важности):**

1. **Планшет 10″** — основной. Портрет ~800×1280 CSS px и ландшафт ~1280×800. Управление пальцем, часто двумя руками, планшет стоит на подставке или лежит на столе.
2. **Телефон** — иногда, 360–430 px по ширине.
3. **Десктоп** — очень редко. Отдельный десктопный интерфейс не делаем; та же планшетная раскладка с `max-width`, плюс необязательные hover-эффекты.

Поэтому проектируем **tablet-first, touch-first**: крупные зоны нажатия, никаких действий, доступных только по hover, обе ориентации, safe-area, удобные отступы под большой палец.

Что для него важно:

- крупные кнопки и понятные иконки;
- короткие задания, которые не утомляют;
- мгновенная реакция на ответ;
- ощущение, что он продвигается и его хвалят;
- никакого наказания за ошибку и никакого «проигрыша».

**Папа.** Хочет видеть, что сын занимается, и иметь код, который можно поддерживать и развивать. Документация должна позволять другому человеку или ИИ-агенту продолжить работу без раскопок.

## 3. Цели, не-цели, анти-цели

### Цели

1. Современный, плотный, «взрослый» интерфейс без пустых полей — на телефоне и на десктопе.
2. Ребёнок 7 лет может начать занятие без помощи взрослого: максимум один понятный выбор.
3. Появляется ощущение прогресса: XP, уровень, звёзды, серия дней, бейджи, цель дня.
4. Сессия длится 5–10 минут; можно выйти в любой момент без стыда и потери уже заработанного.
5. Сохраняются офлайн-режим, озвучка, PWA-установка и существующая анимация заливки слова.
6. Код разложен по модулям, у ключевой логики есть тесты, у проекта есть `AGENTS.md`.

### Не-цели

- Многопользовательский режим, аккаунты, облачная синхронизация.
- Переезд на React/MUI и вообще на фреймворк.
- Серверная база данных, аналитика, родительский кабинет.
- Распознавание речи и микрофон.
- Умножение и деление (можно добавить позже).
- Полноценная i18n: интерфейс только на русском.
- Платежи, уведомления, социальные функции.

### Анти-цели

- Казино-механики: лутбоксы, жизни, таймеры наказания, «сгорающие» награды.
- Красные экраны и стыд за ошибку.
- Анимации, которые нельзя пропустить, и искусственные задержки.
- Перегруженный экран: больше 2–3 акцентов одновременно.
- Поломка офлайна или озвучки ради красоты.

## 4. Выбранный подход

Рассматривались три варианта:

| Вариант | Что делаем | Плюсы | Минусы |
|---|---|---|---|
| **A. Косметика** | Только новая визуальная система, логика не меняется | Быстро, минимум риска | Главная остаётся меню, прогресса нет |
| **B. Умный тренажёр** | Новый UI + дашборд + прогресс/XP/серия/бейджи + настройки + нормальные экраны завершения. Vanilla JS + Tailwind | Максимальный эффект без переезда; сохраняем PWA и озвучку; ребёнку интересно | Средний объём, нужно разложить `app.js` |
| **C. React + MUI** | Полный редизайн на Vite + React + MUI + Tailwind | Буквально MUI, удобно расти | 3–4× работы, больше вес, переписать озвучку/PWA, риск сломать рабочее |

**Выбран B.** MUI — это React-библиотека; тащить React ради шести экранов и одного пользователя нерационально. Нужный material-вид (tonal-поверхности, крупные скругления, elevation, motion) делаем на Tailwind через дизайн-токены и переиспользуемые компоненты.

Отдельно отклонён вариант с `@material/web`: библиотека в режиме поддержки, темизация сложнее, а выигрыш для такого маленького приложения минимален.

## 5. Принципы дизайна

1. **Один экран — одно главное действие.** На главной — выбрать предмет, в уроке — ответить, на завершении — продолжить.
2. **Крупно и по-доброму.** Минимальная зона нажатия 44×44 px, лучше 56–64 px. Ошибка — не катастрофа.
3. **Прогресс виден всегда.** Ребёнок должен понимать, где он, сколько осталось и что он уже заработал.
4. **Спокойная поверхность, яркие акценты.** Фон не соревнуется с заданием.
5. **Движение объясняет, а не развлекает.** Анимация показывает результат, переход или награду. Всё уважает `prefers-reduced-motion`.
6. **Офлайн — normal.** Ни один экран не должен зависеть от сети, кроме самой озвучки Yandex.
7. **Никакого давления.** Нет обратного отсчёта до проигрыша, нет «минус жизнь», нет обязательной серии.
8. **Планшет — главный.** Сначала проверяем 10″ в портрете и ландшафте, потом телефон, потом десктоп. Всё управление — пальцем; hover не считается обязательным.

### 6.3. Форма, отступы, тени

- Базовая сетка: 4 px; основные отступы 8/12/16/24/32/48.
- Радиусы: `12` (мелкое), `16` (инпут), `24` (карточка), `28` (диалог), `999` (pill).
- Тени:
  - `soft`: `0 10px 30px rgba(34,36,44,.08)`
  - `lift`: `0 18px 50px rgba(34,36,44,.14)`
  - `press`: `inset 0 2px 0 rgba(34,36,44,.06)`
- Границы — 1 px `--line`, не чёрные.

### 6.4. Иконки

Только встроенные SVG (stroke 2, 24×24, `currentColor`). Без иконочных шрифтов и CDN. Иконки: дом/учёба, график, шестерёнка, плюс, книга, наушники, динамик, пауза, назад, вперёд, звезда, огонь, замок, галочка, крестик, подсказка.

Иконки складываем в `js/ui/icons.js` как функции, возвращающие SVG-строку, либо в SVG-спрайт в `index.html`. Выбираем функции — их проще использовать в шаблонах.

### 6.5. Маскот Байт

**Байт** — дружелюбный робо-паук: круглая индиговая голова-корпус, два больших глаза, антенна с огоньком, восемь тонких лапок с «суставами». Рисуется инлайн-SVG, без растровых картинок, чтобы масштабироваться и работать офлайн.

Состояния:

- `idle` — лёгкое покачивание, моргание;
- `happy` — глаза-дуги, лапки вверх, используется при правильном ответе;
- `sad` — глаза вниз, но без слёз и драмы, при ошибке;
- `think` — один глаз прищурен, лапка у головы, в подсказках;
- `sleep` — для пустых состояний;
- `party` — конфетти и подпрыгивание на завершении.

Где живёт:

- главная — герой-карточка с приветствием и репликой;
- завершение сессии — поздравление;
- пустой прогресс — «Пока пусто, но мы это исправим»;
- тосты с бейджами — маленькая версия.

Не ставим маскота на каждый экран: он не должен мешать решать примеры. В уроке — только маленькая реакция в фидбэке.

### 6.6. Фон и декор

- Мягкие радиальные пятна в углах фона (`radial-gradient`), очень низкая непрозрачность.
- Едва заметный «паутинно-пластинчатый» паттерн: тонкие линии/точки, 3–5% непрозрачности.
- Никаких тяжёлых фоновых фотографий. `background.jpg` не используется — удалить из репозитория или оставить вне сборки; в дизайне он не нужен.
- На экранах урока фон спокойнее: почти однотонный `--bg` с тонкой сеткой.

## 7. Информационная архитектура

```
App shell
├── Учиться            #/
│   ├── Математика     #/play/math
│   ├── Чтение         #/play/reading
│   └── Тест на слух   #/play/test
├── Прогресс           #/progress
└── Настройки          #/settings

Завершение сессии — состояние внутри #/play/*, не отдельный маршрут.
```

- **Телефон:** нижняя навигация (Material 3 navigation bar) с тремя пунктами: Учиться, Прогресс, Настройки. Высота 64 px + safe-area.
- **Планшет (touch, любая ориентация):** плавающая нижняя панель-«пилюля» по центру, max-width 520 px, три пункта, отступ 16 px + safe-area. Так до кнопок удобно дотягиваться большими пальцами, и они не разъезжаются по всей ширине 10″ экрана.
- **Десктоп с мышью (редко):** только при `min-width: 1024px` и `hover: hover` + `pointer: fine` — левый navigation rail 248 px: логотип, три пункта, внизу маленький Байт и версия. На планшете с touch этого rail нет, даже если ширина 1280 px.
- **Фокус-режим урока/теста:** навигация скрывается, сверху app bar с кнопкой «назад», названием, таймером и звуком. Выход — через подтверждение, если сессия не завершена.
- Роутинг — hash-based (`#/...`), чтобы работала кнопка «назад» браузера и можно было давать прямые ссылки. При прямом открытии `#/play/*` без активной сессии показываем главную и короткий тост «Выбери урок».
- Название приложения остаётся «Ярик.Уроки», в hero — подпись «Уроки с Байтом».

## 8. Экраны

### 8.1. Главная «Учиться»

**Раскладка по устройствам:**

- **Телефон:** одна колонка, hero вертикальный, предметы друг под другом.
- **Планшет, портрет:** hero в две колонки (текст + Байт), переключатель сложности, три карточки предметов в один ряд.
- **Планшет, ландшафт:** двухколоночная сетка: слева hero и предметы, справа цель дня, серия и мини-прогресс; при нехватке высоты — обычный вертикальный скролл, без сжатия контента.
- **Десктоп:** та же планшетная сетка, контент max-width 1120 px, без отдельной «десктопной» версии.

Состав сверху вниз:

1. **App bar / greeting**
   - «Привет, Ярик!» (имя из настроек) + маленькая дата/день.
   - Справа — чип уровня `Ур. 4` и шестерёнка (на мобильном).
2. **Hero-карточка**
   - Слева: приветствие, короткая реплика Байта («Сегодня потренируем лапки?»), кнопка «Продолжить» не нужна — ниже предметы.
   - Справа: Байт `idle`.
   - Внизу hero: цель дня — кольцо `7/10 мин` и серия `🔥 3 дня`.
3. **Переключатель сложности**
   - Material segmented control: «Лёгкий» / «Сложный».
   - Влияет на математику и чтение; выбор сохраняется в настройках.
   - Рядом подпись, что именно значит уровень: «Сложение до 10» / «Примеры до 20».
4. **Карточки предметов** (3 шт.)
   - Математика: иконка «плюс/цифры», «Сложение и вычитание», последний результат «9/10».
   - Чтение: иконка книги, «Слоги, слова и фразы», «12 карточек за последний раз».
   - Тест: иконка наушников, «Слушай и выбирай», «8/10 в прошлый раз».
   - Вся карточка — кнопка; hover/press; справа стрелка.
5. **Мини-прогресс**
   - Полоса XP до следующего уровня, звёзды, 2–3 последних бейджа.
   - Кнопка «Весь прогресс» ведёт на `#/progress`.
6. **Footer**
   - Версия, «Сделано для Ярика», кнопка обновления появляется баннером.

Пустые состояния: если данных нет, вместо последних результатов — «Первый раз? Начни с математики» и Байт `happy`.

### 8.2. Математика `#/play/math`

**Раскладка:** телефон и планшет-портрет — вертикально; планшет-ландшафт — две колонки: уравнение слева, клавиатура справа (см. 12).

- **App bar:** назад (с подтверждением), «Математика», чип уровня, маленький таймер `00:00`, кнопка звука.
- **Прогресс:** 10 сегментов; заполненные — янтарные; подпись «3 / 10».
- **Карточка задания:**
  - крупное уравнение `5 + 7 = ?`;
  - ответ в отдельном «слоте» с мигающим курсором;
  - под уравнением — кнопка «Подсказка» (опционально, см. ниже).
- **Ввод:**
  - цифровая клавиатура 3×4: `1–9`, `⌫`, `0`, `Проверить`;
  - кнопки 64–72 px, крупный шрифт;
  - на десктопе работают цифры, `Backspace`, `Enter`.
- **Проверка:** только по кнопке/Enter, без автоотправки через 2 секунды. Это убирает неожиданность.
- **Фидбэк:**
  - правильно: зелёная плашка, Байт `happy`, +10 XP начисляется сразу, через 900 мс — следующее задание;
  - неправильно: янтарная (не красная) плашка «Почти! Правильный ответ — 12», показываем верный ответ, через 2 секунды — следующее;
  - ошибка засчитывается в статистику, но не отнимает XP и не блокирует урок.
- **Подсказка (в объёме, если успеваем):** для сложения — две группы точек; для вычитания — предметы с зачёркнутыми. Кнопка не обязательна для завершения. Если реализация затягивается, вынести в фазу 2 и не блокировать релиз.
- **Что сохраняется при досрочном выходе:** каждый ответ пишется в store сразу — XP, правильные/всего, время. Если Ярик ответил на 9 из 10 и вышел, 90 XP и 9 правильных ответов остаются, но сессия не считается завершённой: нет звёзд, бонуса за завершение, истории, серии и бейджей за завершение. Так «заработанное» не сгорает, но и бросить урок на первом ответе ради серии не получится.
- **Левел-ап и бейджи** не показываем посреди урока, чтобы не отвлекать: награды и поздравления появляются на экране результата или на главной после возврата.
- **Завершение:** экран результата (см. 8.5).

### 8.3. Чтение `#/play/reading`

**Раскладка:** телефон и планшет-портрет — вертикально; планшет-ландшафт — карточка слова слева, кнопка «Послушать» и навигация справа.

- **App bar:** назад, «Чтение», уровень, таймер, звук.
- **Прогресс:** «5 / 20» + непрерывная полоса.
- **Карточка слова:**
  - крупное слово или фраза по центру;
  - гласные — янтарные, согласные — чернильные; слоги разделены тонкой точкой/дугой, а не дефисом-как-текстом;
  - при озвучке — существующая синхронная заливка букв;
  - ниже — большая кнопка «Послушать» с иконкой динамика и пульсирующими волнами во время речи.
- **Автоозвучка:** при открытии слова включается автоматически, если звук включён. Повторное нажатие — переозвучить. При смене слова предыдущая озвучка отменяется.
- **Навигация:** «Назад» / «Далее» крупными pill-кнопками; на телефоне и планшете — внизу, над safe-area; на десктопе — по бокам карточки. Клавиши ←/→.
- **Единица прогресса — карточка:** одно слово в лёгком режиме или одна фраза в сложном. Это одна единица для «5 / 20», `cardsRead`, +2 XP и бейджа «Читатель». Фраза не делится на слова для начисления.
- **Повторное чтение:** возврат «Назад» и повторное открытие карточки не начисляют XP второй раз. В сессии хранится набор уже засчитанных карточек.
- **Завершение:** после 20 карточек или по кнопке «Завершить». Если прочитана хотя бы одна карточка, сессия считается завершённой: звёзды 3 — все 20, 2 — ≥14, 1 — ≥1; сессия, серия, история и бонус за завершение начисляются. Если нажал «Завершить» на 0 карточек — просто выход без записи сессии. При выходе через «Назад» показываем подтверждение «Выйти? Прочитанные карточки сохранятся».
- **Без оценок за правильность:** это практика, а не экзамен. Звёзды — за объём завершённой практики, а не за «ошибки». В конце — «Ты прочитал 20 карточек!».

### 8.4. Тест на слух `#/play/test`

**Раскладка:** телефон и планшет-портрет — вертикально; планшет-ландшафт — скрытое слово и «Послушать» слева, варианты справа.

- **App bar:** назад, «Тест на слух», таймер, звук.
- **Прогресс:** 10 вопросов.
- **Скрытое слово:**
  - вместо случайных символов — ряд одинаковых плиток `?` (по числу букв); это выглядит как игра и не путает;
  - во время озвучки плитки подсвечиваются слева направо синхронно с речью (переиспользуем прогресс-анимацию);
  - после правильного ответа плитки по очереди переворачиваются в настоящие буквы (текущая анимация reveal).
- **Кнопка «Послушать»:** большая, с волнами; можно нажимать сколько угодно до ответа. Явная кнопка решает текущую проблему «надо догадаться, что слово кликабельно».
- **Варианты:** 3 крупные карточки; клавиши 1/2/3; при ошибке — shake, подсветка правильного варианта, показ слова, переход через 1,8 с. Одна попытка на вопрос; правильность считается по первому ответу, чтобы результат был честным.
- **Завершение:** экран результата.

### 8.5. Экран завершения сессии

Общий компонент для математики, чтения и теста:

- Байт `party`, конфетти (CSS/canvas, 1,2 с, отключается при reduced motion).
- Заголовок: «Отлично!», «Хорошо!» или «Готово!» в зависимости от результата.
- **Звёзды 1–3** — главный результат:
  - математика/тест: 3 звезды ≥90%, 2 ≥70%, 1 — за завершение;
  - чтение: 3 — все 20 карточек, 2 — ≥14, 1 — ≥1.
- Вторичные цифры: `9 из 10`, оценка `9` (старая шкала 1–10 остаётся маленьким чипом), время, заработанный XP.
- Если новый уровень — плашка «Новый уровень 5!».
- Если новый бейдж — карточка бейджа с названием.
- Кнопки: «Ещё раз» (primary), «На главную» (tonal).
- **Досрочный выход:** математика/тест — ответы и XP сохраняются сразу, но экран результата не показывается и сессия не считается завершённой; чтение — при выходе после ≥1 карточки сохраняется частичная сессия со звёздами по объёму (см. 8.3). Это компромисс: ребёнок не теряет заработанное, но серия и бейджи не начисляются за «зашёл и вышел».

### 8.6. Прогресс `#/progress`

- Заголовок «Твой прогресс» + Байт `happy`.
- **Верхние плитки:**
  - уровень и XP-полоса до следующего;
  - серия: текущая и лучшая, 7 точек последних дней;
  - всего звёзд.
- **Предметы:**
  - математика: точность `%`, лучший результат, сессий;
  - чтение: карточек прочитано, сессий, время;
  - тест: точность `%`, лучший результат, сессий.
- **Бейджи:** сетка 3×N; открытые — цветные, закрытые — серые с замком и подсказкой условия.
- **История:** последние 10 сессий: дата, тип, результат, звёзды. Прокручиваемый список.
- **Пусто:** Байт `sleep`, «Пока здесь тихо. Начни первый урок — и я всё запишу».

### 8.7. Настройки `#/settings`

- **Профиль:** имя (input, 1–20 символов, сохраняется по blur/Enter), аватар — Байт (фиксирован).
- **Звук:** мастер-переключатель озвучки; отдельный переключатель звуковых эффектов (правильно/неправильно).
- **Сложность:** segmented «Лёгкий» / «Сложный» с пояснением.
- **Тема:** «Светлая» / «Тёмная» / «Как в системе»; применяется сразу, сохраняется.
- **Сброс прогресса:** danger-кнопка, диалог подтверждения: «Сбросить XP, уровень, серию, бейджи и историю? Имя, тема, звук и сложность останутся». Удаляет только ключ прогресса `yarik.uroki.progress.v1`, не трогает `yarik.uroki.settings.v1`, затем перезагружает приложение. Полный сброс всего — через очистку данных сайта браузером.
- **О приложении:** версия, «Сделано для Ярика», «Байт одобряет», ссылка на `AGENTS.md`? Ссылку на документацию в UI не обязательно; версия и авторство достаточно.
- **Родительская зона** не делаем: приложение персональное.

### 8.8. Служебные элементы

- **Тосты** (snackbar): XP, новый бейдж, «Не удалось озвучить», «Выбери урок». Появляются снизу над навигацией, 3–4 с, не перекрывают кнопки.
- **Диалоги:** нативный `<dialog>` с focus trap; «Выйти из урока?», «Сбросить прогресс?».
- **Баннер обновления:** сохраняем ID (`update-banner`, `update-btn`, `update-text`, `update-progress-container`, `update-progress-bar`), чтобы не ломать `update-notifier.js`; стилизуем как нижний snackbar с прогрессом.
- **Лоадер:** только на самом первом boot (если нужно) — скелетон/маскот, без искусственной задержки. При навигации — мгновенно.
- **Ошибки озвучки:** тихий fallback; если не сработало — тост «Не получилось озвучить. Попробуй ещё раз», интерфейс продолжает работать.

## 9. Геймификация и прогресс

### 9.1. XP

| Действие | XP |
|---|---|
| Правильный ответ в математике | +10 |
| Правильный ответ в тесте | +10 |
| Уникальная прочитанная карточка за сессию | +2 |
| Завершение сессии | +5 |
| Идеальная сессия (100%, только математика и тест) | +20 |
| Первая завершённая сессия за день | +10 |
| Открытие нового бейджа | +25 |

- XP за ответы и карточки начисляется сразу и не сгорает при досрочном выходе.
- Бонусы за завершение, идеальную сессию, первую сессию дня и бейджи — только при завершённой сессии.
- В чтении нет «идеальной» сессии: там нет ошибок. Полные 20 карточек дают обычный бонус за завершение, без +20.
- XP не отнимается. Ошибки не штрафуются.

### 9.2. Уровни

- Уровень = `floor(totalXp / 100) + 1`.
- Внутри уровня — полоса `totalXp % 100`.
- После 20 уровня — титул «Мастер Байта», полоса продолжает расти.
- Левел-ап показываем на экране завершения и тостом. Если уровень вырос посреди урока, он уже сохранён, но поздравление не прерывает задание: покажем его на результате или на главной после возврата.

### 9.3. Звёзды

- Храним лучший результат по предмету и звёзды за сессию.
- Звёзды показываем на завершении и в истории, не в виде «жизней».

### 9.4. Серия дней

- День считается активным, если завершена хотя бы одна сессия.
- Завершённая сессия: математика/тест — все 10 заданий; чтение — прочитана минимум одна карточка и сессия закрыта кнопкой «Завершить» или подтверждённым выходом. Досрочно брошенная математика/тест серию не продлевает.
- Если последняя активная дата — вчера, серия +1; если сегодня — не меняется; если раньше — серия = 1.
- Лучшая серия хранится отдельно.
- В интерфейсе: `🔥 3 дня`; если сегодня ещё не занимался — мягкая подпись «Зайди сегодня, чтобы сохранить серию».

### 9.5. Цель дня

- 10 минут активного времени за день (таймер сессии).
- Кольцо на главной: `7 / 10 мин`.
- Время фиксируется каждые 30 секунд и при выходе/завершении, поэтому даже досрочно брошенная сессия добавляет минуты к цели дня. XP за ответы при этом тоже сохраняется.
- После достижения — «Цель дня выполнена!» и +20 XP один раз в день.
- Время считается только на экранах урока/теста/чтения, не на главной и не в настройках.

### 9.6. Бейджи

Стартовый набор (названия можно слегка менять, условия — нет):

| ID | Название | Условие |
|---|---|---|
| `first-step` | Первый шаг | Первая завершённая сессия |
| `streak-3` | Три дня подряд | Серия 3 |
| `streak-7` | Неделя с Байтом | Серия 7 |
| `math-50` | Математик | 50 правильных ответов в математике |
| `test-50` | Острый слух | 50 правильных ответов в тесте |
| `reader-100` | Читатель | 100 прочитанных карточек |
| `perfect-math` | Без единой ошибки | Математика 10/10 |
| `perfect-test` | Идеальный слух | Тест 10/10 |
| `all-subjects` | Восемь лапок | По одной сессии каждого предмета |
| `level-5` | Пятый уровень | Достигнут уровень 5 |

- Открытие — тост + запись в `badges` с датой и +25 XP.
- Условия проверяются при завершении сессии и при загрузке приложения; посреди урока бейджи не всплывают.
- Повторно не открывается.
- В прогресс-экране у закрытых — условие.

### 9.7. Тон текстов

- Хвалим усилие и процесс: «Отлично!», «Ты справился!», «Байт гордится тобой!».
- Ошибка: «Почти!», «Ничего страшного, попробуем ещё», «Даже роботы учатся».
- Без сарказма, без «позора», без обращения «малыш» и без сложных слов.
- Фразы короткие, 2–6 слов.
- Персонализация: имя из настроек, но не в каждом предложении.

## 10. Контент

### 10.1. Математика

- **Лёгкий:** сложение в пределах 10 (как сейчас).
- **Сложный:** сложение и вычитание в пределах 20, без отрицательных результатов.
- 10 заданий за сессию.
- Данные генерируются, а не хранятся огромным массивом; для тестов — чистая функция `generateMathProblems(level, count, rng?)`.
- Формат: `{ num1, num2, operator: '+' | '-', answer }`.

### 10.2. Чтение

Новый формат данных вместо дефисов внутри слова:

```js
{ text: 'СОБАКА', syllables: ['СО', 'БА', 'КА'] }
{ text: 'Робот чинит мотор', syllables: null } // фраза
```

Почему: дефис больше не является разметкой; фразы с дефисом («робот-паук») не ломают рендер; данные чище для агентов.

Наборы:

- **Лёгкий:** слоги и короткие слова, 20 случайных карточек из пула.
- **Сложный:** фразы, 20 случайных карточек из пула.
- Одна карточка = одно слово (лёгкий) или одна фраза (сложный) для прогресса, XP и бейджа.
- Добавляем тематический набор «Роботы и пауки»:
  - `РОБОТ`, `ПАУК`, `ЛАМПА`, `ВИНТ`, `ГАЙКА`, `МОТОР`, `ПУЛЬТ`, `ПРОВОД`, `КНОПКА`, `БАТАРЕЯ`;
  - фразы: «Робот чинит мотор», «Паук плетёт сеть», «Восемь лапок из металла», «Байт мигает огоньками», «Паучок собирает гайки», «На спине у паука радар».
- Тематические слова не заменяют базовые, а добавляются в пул.

### 10.3. Тест на слух

- 10 вопросов за сессию (было 20; для 7 лет короче и комфортнее).
- Пул — 30+ слов, включая тематические: `РОБОТ`, `ПАУК`, `ВИНТ`, `ГАЙКА`, `МОТОР`, `КНОПКА`, `АНТЕННА`, `БАТАРЕЯ`.
- Формат: `{ word, options: [correct, similar1, similar2] }`; правильный вариант обязательно присутствует ровно один раз.
- Дистракторы — похожие по звучанию/форме слова, как сейчас.
- Перемешиваем и вопросы, и варианты.

### 10.4. Фразы обратной связи

- Правильные: «Отлично!», «Байт гордится тобой!», «Ты справился!», «Верно!», «Супер!».
- Неправильные: «Почти!», «Ничего страшного», «Попробуем ещё», «Даже роботы учатся».
- Убрать «пирожок» и слишком детские обращения, если они не нравятся семье; тон — дружелюбный, но не сюсюкающий.

### 11.2. Рендеринг и экраны

- Без фреймворка. Каждый экран — модуль с функцией `render(container, ctx)`, которая возвращает `destroy()`.
- Роутер при смене маршрута вызывает `destroy()` предыдущего экрана: очищает таймеры, отменяет озвучку, снимает слушатели.
- Разметка — шаблонные строки + DOM API. Пользовательские данные (имя) экранируются.
- Общий shell в `index.html`: `<main id="view-root">`, `<nav>`, `<div id="overlay-root">`, контейнер тостов, баннер обновления, `<dialog>`-контейнер.
- Фокус-режим: shell скрывает навигацию, экран занимает viewport.

### 11.3. Роутер

- Маршруты: `#/`, `#/progress`, `#/settings`, `#/play/math`, `#/play/reading`, `#/play/test`.
- `navigate(path, { replace })`; слушаем `hashchange` и `popstate`.
- Прямой заход на `#/play/*` без `sessionStorage`-флага активной сессии → редирект на `#/` + тост.
- Выход из активной сессии по «назад» — диалог подтверждения. `beforeunload` не используем (раздражает); hash-навигация достаточна.
- После завершения сессии маршрут остаётся `#/play/*`, экран результата — состояние; «На главную» ведёт на `#/`.

### 11.4. Состояние

Два ключа, чтобы «Сбросить прогресс» не стирал имя, тему и настройки. Store — единственный источник состояния, глобальных переменных в экранах нет.

```js
// Настройки и профиль
'yarik.uroki.settings.v1'
{
  version: 1,
  profile: { name: 'Ярик' },
  settings: {
    sound: true,
    effects: true,
    difficulty: 'easy',      // 'easy' | 'hard'
    theme: 'system'           // 'light' | 'dark' | 'system'
  }
}

// Прогресс
'yarik.uroki.progress.v1'
{
  version: 1,
  xp: 340,
  level: 4,                   // вычисляется и кэшируется
  streak: {
    current: 3,
    best: 7,
    lastActiveDate: '2026-11-26',
    activeDays: ['2026-11-24', '2026-11-25', '2026-11-26']
  },
  daily: {
    date: '2026-11-26',
    seconds: 420,
    goalSeconds: 600,
    goalBonusGiven: false
  },
  subjects: {
    math:    { sessions: 4, correct: 31, total: 40, bestStars: 3, lastPlayed: '...', totalSeconds: 500 },
    reading: { sessions: 2, cardsRead: 40, bestStars: 3, lastPlayed: '...', totalSeconds: 300 },
    test:    { sessions: 1, correct: 8, total: 10, bestStars: 2, lastPlayed: '...', totalSeconds: 180 }
  },
  badges: { 'first-step': '2026-11-20', 'streak-3': '2026-11-26' },
  history: [
    { type: 'math', date: '2026-11-26T17:20:00', correct: 9, total: 10, stars: 3, durationSec: 120, xp: 100 }
  ]
}
```

**API store:**

- `loadSettings()`, `loadProgress()`, `getSettings()`, `getProgress()`, `updateSettings(partial)`.
- `recordAnswer({ type, correct })` — сразу пишет XP, `subjects[type].correct/total`, возвращает `{ xpGained, levelUp }`. Вызывается на каждый ответ математики/теста.
- `recordReadingCard(cardId)` — начисляет +2 XP и `cardsRead` только за уникальную карточку; набор уникальных ID ведёт экран сессии.
- `recordTime(seconds)` — добавляет секунды к цели дня; вызывается каждые 30 секунд и при выходе.
- `recordSession({ type, correct, total, durationSec, stars })` — завершение: +5 XP, первая сессия дня +10, идеальная +20 (только математика/тест), обновляет `sessions`, `bestStars`, `history`, `streak`, проверяет бейджи. Возвращает `{ bonusXp, levelUp, newBadges, dailyGoalReached, streak }`.
- `resetProgress()` — удаляет только `yarik.uroki.progress.v1`.
- `getLevelInfo()` — уровень, XP внутри уровня, сколько до следующего.

**Правила:**

- XP за ответы и карточки сохраняется сразу; бонусы — только при завершённой сессии.
- Экран завершения суммирует `xpGained` от ответов/карточек + `bonusXp`.
- `history` — не больше 30 записей; `activeDays` — не больше 30 дат.
- `daily` сбрасывается при смене локальной даты; `recordTime` после полуночи создаёт новую запись.
- Ошибки чтения/записи localStorage не роняют приложение: fallback в память + тост.
- Ключ `yarik_uroki_updated_to` из `update-notifier.js` не трогаем.

### 11.5. Таймер

- `createSessionTimer({ onTick })`: старт, пауза, стоп, `getSeconds()`.
- При `document.hidden` — пауза, при возврате — продолжение.
- Время фиксируется в store каждые 30 секунд и при завершении/выходе, поэтому минуты не теряются при досрочном уходе.
- Таймер не создаёт давление: маленький чип, без красного цвета и без обратного отсчёта.

### 11.6. Озвучка

- Оставляем `speech-service.js` и `window.speechService` без переписывания.
- `js/speech.js` — тонкая обёртка:
  - `speak(text, { isWord, onProgress })` — Yandex, если доступен, иначе браузерный fallback;
  - `cancel()`, `isEnabled()`, `unlock()` (первый жест);
  - отмена при смене маршрута и при смене слова.
- Fallback-логику браузерного синтеза переносим из `app.js` в `speech.js`, чтобы не дублировать.
- `onProgress` сохраняем для заливки букв.
- При ошибке — тост, но интерфейс не блокируется.
- Автоплей: первый звук запускается после клика «Начать»/перехода; дальше — по слову.

### 11.7. Стили

- Tailwind 4 + CSS-переменные. Тёмная тема через класс `.dark` на `<html>` и `@custom-variant dark`.
- `src/input.css` импортирует `tokens.css`, `base.css`, `components.css`, `animations.css`.
- `@source` явно указывает `./js/**/*.js`, чтобы Tailwind видел классы в шаблонных строках.
- Компонентные классы: `.btn`, `.btn-primary`, `.btn-tonal`, `.card`, `.chip`, `.segmented`, `.field`, `.dialog`, `.toast`, `.stat-tile`, `.subject-card`, `.star`.
- Утилитарные классы Tailwind — для раскладки; сложные повторяемые вещи — в компонентах.
- `styles.css` генерируется `npm run build:css`; никогда не редактируется вручную.

## 12. Адаптивность

**Приоритет проверки:** сначала 10″ планшет в портрете и ландшафте, потом телефон, десктоп — в конце. Планшетная раскладка — основная; десктоп не получает отдельный дизайн.

| Ширина / устройство | Поведение |
|---|---|
| 320–479, телефон | Одна колонка; нижняя навигация; hero вертикальный; предметы друг под другом; крупные кнопки |
| 480–767, крупный телефон | Одна колонка; больше воздуха; предметы можно 2+1 |
| 768–1023, планшет портрет | Hero в две колонки; три предмета в ряд; плавающая нижняя панель; контент max 960 px |
| 1024–1279, планшет ландшафт | Двухколоночная сетка; три предмета в ряд; плавающая панель; урок — две колонки (контент + управление), max 1100 px |
| ≥1280, планшет ландшафт / десктоп | Контент max 1120 px; на touch — плавающая панель; на мыши — rail. Урок max 1100 px, внутри — две колонки |
| Низкий landscape (высота < 600) | Скрываем маскота и крупный декор, компактный header, контент прокручивается |

**Как раскладываются уроки на планшете в ландшафте:**

- Математика: слева уравнение и фидбэк (7/12), справа цифровая клавиатура (5/12); прогресс сверху на всю ширину.
- Чтение: слева карточка слова (7/12), справа крупная кнопка «Послушать», подсказка и навигация (5/12).
- Тест: слева скрытое слово и кнопка «Послушать» (6/12), справа три варианта (6/12).
- Завершение: центрированная карточка max 560 px.

Правила:

- Никакого горизонтального скролла на 320 px.
- На планшете в портрете урок — центрированная карточка max 760 px; в ландшафте — максимум 1100 px с двумя колонками.
- Safe-area insets: `env(safe-area-inset-*)` для iPad/iPhone.
- Кнопки не меньше 44 px; основные — 56–64 px.
- Никаких действий только по hover: hover — необязательное улучшение через `@media (hover: hover)`.
- Планшет не должен выглядеть как растянутый телефон: используем две колонки и заполняем ширину карточками, а не пустотой.
- Ориентация не блокируется: обе поддерживаются, `manifest.orientation: any`.

## 13. Доступность

- `<main>`, `<nav>`, `<header>`, один `<h1>` на экран.
- Все интерактивные элементы — настоящие `<button>`/`<a>`, не `div` с role, где можно избежать.
- `focus-visible` ring `--focus`, не убирать outline без замены.
- Иконки-кнопки имеют `aria-label`; переключатели — `aria-pressed`/`aria-checked`.
- Фидбэк — `role="status" aria-live="polite"`.
- Не полагаться только на цвет: правильный ответ — галочка + текст, ошибка — иконка + текст.
- Контраст текста ≥ 4.5:1, крупного — ≥ 3:1.
- `prefers-reduced-motion`: отключаем конфетти, пульсации, большие перемещения; оставляем мгновенные состояния.
- Диалоги — нативный `<dialog>` с возвратом фокуса.
- Клавиатура: цифры/Enter/Backspace в математике, 1–3 в тесте, ←/→ в чтении, Esc — закрыть диалог.
- Экран не должен «прыгать» при появлении тостов.

## 14. Производительность

- Ноль внешних JS/CSS-библиотек; только локальные шрифты.
- Никаких искусственных задержек; анимации 150–400 мс, только `transform`/`opacity`.
- Не более одного `requestAnimationFrame`-цикла на анимацию; отменять при уходе с экрана.
- Не хранить тяжёлые DOM-деревья; экраны рендерятся заново.
- Кэш PWA — network-first, офлайн fallback.
- Цель: первый интерактив без «чёрного экрана» и без мигания; Lighthouse best practices ≥95.
